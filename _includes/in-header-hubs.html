It is sticky (main.css), so it stays in reach on scroll while the breadcrumb scrolls away. Items and their order come from _data/nav.yml `topnav` (type home | menu | tile; a menu has children and/or nodes). Each menu is a
, so it works without JS; the site.js "Page control" block keeps one open at a time and closes it on outside click and Escape. The row is one line at every width and scrolls sideways when it does not fit; panels hang off the nav itself (not the scrolling strip), so the strip's overflow never clips them. Plain menus (children only) are a short list of links with a one-line description. Mega menus (a menu with `nodes`): the panel is a two-pane matrix. Left: a rail with the node names only (plus any `children` links under a rule). Right: the active node's columns — every guide in that category, names only, flowed into as many columns as fit, so nothing needs scrolling. A node's columns come from its own `cols` or, with `mega: `, from _data/nav_mega.yml (built by scripts/build-nav-mega.mjs from the hub pages). Desktop with a mouse (>=1024px, hover): hovering or focusing a rail name swaps the right pane at once (site.js moves .is-on; the first node starts on). Touch and below 1024px: each rail name is an accordion that opens its list under it. Cascade selector (2026-10-21): a node with 2+ groups and more than 8 guides becomes three columns on desktop — rail (hover), its groups as a vertical list (states, sub-streams, sport families), and the picked group's links only. A group is picked by click / tap / arrow keys, never by hover; site.js moves .is-on between .hh-tab and the .hh-col its aria-controls names. More than 10 groups (states) sit in two short columns in column 2 (.hh-tabbed-2). Narrow: the groups are a sideways pill line above the list. Column 3 cells (.hh-cell, cascade nodes only): each link is a ruled cell in a grid — mono index, name, its one-line desc shown (instead of a title tooltip), mono arrow — so a long group reads as a scannable board. USA edition (2026-10-23): the layout includes this with edition="us" on every us/** page (body.shell-us, no sidebar). Items then come from _data/nav_us.yml `topnav` and `mega` keys from _data/us/nav_mega.yml (built by scripts/build-us-nav-mega.mjs). A menu with `clusters: true` draws one rail node per live cluster of _data/us/clusters.yml (name, hub us/clusters//, mega key cluster-), so the rail follows the data. Category badges (2026-10-24): a rail node with `badge: stem | health | finance` (for clusters, the menu's `badges` map by slug) gets a small mono tag after its name (.hh-nav-badge).
